# 표준적합성시험 웹 연결

DATEX·REST API·TCP/Binary·Kafka 실행기를 공통 Chrome 확장 하나로 연결한다. 기존 REST 확장의 ID `hkcbopjignhkclfmejopkpkpmdlpnmba`와 권한 범위를 유지한다.

## 사용 순서

1. 진행 중인 시험을 마친다.
2. Chrome 확장 관리에서 기존 **REST API 웹 시험 연결**을 새로고침한다. 이름이 **표준적합성시험 웹 연결**로 표시되는지 확인한다. 같은 ID이므로 중복 설치하지 않는다.
3. 이전 **DATEX 웹 시험 연결**은 끈다. 새 DATEX 실행기도 공통 확장을 사용한다.
4. 시험 페이지를 새로 열고 새 실행기에서 환경설정 → 웹 적용 → 시작 순서로 진행한다.

이 PC의 기존 REST v1 확장 폴더와 최신 묶음의 `Chrome-연결-확장`에 갱신 파일을 제공한다. 다른 위치에서 설치했다면 그 폴더를 확인해 공통 확장 파일로 갱신한다. 설치하지 않은 PC는 제공한 `표준적합성시험-웹-연결` 폴더를 불러온다. 브라우저 확장 갱신/비활성화는 Chrome에서 직접 처리한다.

## 여러 시험을 함께 실행

- 실행기 창을 필요한 만큼 열고, 각 Chrome 창 또는 탭에서 **서로 다른 자체 시험 회차**를 만든다. 각 Agent URL을 대응하는 실행기에 넣는다. 같은 실행기 프로그램도 여러 번 열 수 있다.
- 같은 Windows 사용자에서 최대 **16개 회차의 실행기 연결**을 지원한다. 실제 실행 가능한 시험 수는 PC와 시험 대상의 자원에 따른다.
- 설정·시작·종료는 회차와 브라우저 문서에 묶는다. 한 창을 중지해도 다른 회차는 계속 실행한다. 같은 회차를 여러 실행기가 제어하는 것은 거부한다.
- 실행기에서 설정 적용 시 로컬 상대 포트가 충돌하면 빈 포트로 조정하고 **변경한 값을 웹 화면에 표시**한다. 웹에서 직접 입력한 포트가 충돌하면 재설정을 안내한다.
- 다른 Chrome 프로필을 사용하면 해당 프로필에도 같은 공통 확장이 활성화되어 있어야 한다.

## 범위와 유지보수

공통 확장의 원본은 `interfaceconformance/launcher/chrome-extension`, 공통 C# 연결부는 `WebFormLink.cs`와 `PortReservation.cs`다. 각 실행기의 시험 구성/엔진/판정/기록은 별개이며, 이 변경은 시험 로직 통합을 뜻하지 않는다.

연결 슬롯은 Loopback 43763~43778이다. `X-Rest-Extension` 헤더 이름은 기존 호환을 위해 유지한다. 권한 추가, 로그인 정보 수집, 임의 웹 접근은 하지 않는다. 데이터/설정은 회차·문서·클라이언트·임의 토큰을 대조한 뒤 전달한다. 응답이 불명확한 변경 요청은 자동 재전송하지 않는다.

이전 실행기 묶음과 과거 시험 기록은 유지한다. 동시 연결에는 공통 연결부가 포함된 새 실행기 묶음을 사용한다.
