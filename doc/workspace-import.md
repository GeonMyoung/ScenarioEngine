# 경찰청 ScenarioEngine 저장소 초기 통합

## 목적과 범위

- 기준일: 2026-09-15.
- 원본: `police-test-platform/engine`의 현재 작업 파일.
- 목적지: `GeonMyoung/ScenarioEngine` GitHub 저장소.
- 사용자 확정 범위: engine의 전체 개발 프로젝트와 빌드에 필요한 공통 SDK.
- 30개 모듈, 원본 파일 4,044개, 총 66,209,507바이트를 가져왔다.
- `fe`, `engine_x`, `scenarioengine자료` 과제 자료 묶음은 이 통합 대상이 아니다.
- 모듈별 Git 이력은 원본에 보존한다. 이 저장소는 현재 작업 파일 스냅샷에서 시작한다.
- 원본 폴더와 원본의 미커밋 변경은 수정하지 않았다.

`dependencies.lock.json`에는 모듈별 원본 커밋, 브랜치, 당시 변경 파일 수와 SDK
아카이브 해시를 기록했다. `import-source-manifest.json`은 가져온 원본 파일의
경로·크기·SHA-256을 기록한다. 이후 개발 변경 시 이 초기 원본 기록은 유지한다.

## 구성 변경

1. 네 공통 SDK 정션을 실제 디렉터리와 소스로 옮겼다.
2. 각 모듈의 중첩 `.git`과 `.gitignore`를 가져오지 않고 저장소 루트에서 관리한다.
3. 기존 C/C++ 파일의 인코딩과 줄바꿈을 그대로 유지한다.
4. OpenSSL 1.1.1q의 x64 헤더·라이브러리·런타임 DLL·라이선스 안내를 별도
   빌드용 아카이브로 묶고 Git LFS로 관리한다. 테스트 데이터와 샘플 개인키는 제외한다.
5. `Directory.Build.props`로 SDK 경로를 현재 체크아웃의 `.deps/sdk`에 고정한다.
6. `Directory.Build.targets`로 저장된 생성 소스를 기본 빌드 입력으로 사용하고
   실행 파일 출력 폴더에 런타임 DLL을 복사한다.
7. 설치, 구조 검증, 대상별 빌드와 MSI 입력 준비 스크립트를 추가한다.
8. `ITSK00144_2Emulator.vcxproj`와 `ITSK00144_2EmulatorTest.vcxproj`의
   Release x64 설정에 누락된 `ITSK00144_2TestMsg/include`를 추가했다.
   Debug에 이미 있는 경로와 맞췄으며 시험 로직 소스는 변경하지 않았다.

## 생성 소스를 기본으로 빌드하는 이유

원본에는 직접 수정된 생성 소스와 `.tdc`/`.tjsonc` 정의가 함께 존재한다.
처음 체크아웃한 PC에서 CustomBuild를 무조건 실행하면 기존 작업 파일을
덮어쓸 수 있다. 기본 빌드는 버전 관리된 생성 소스를 사용한다.
생성 도구는 `-Target Tools`로 소스에서 만들 수 있으며, 스키마를 변경한 모듈만
`ScenarioEngineRegenerateSources=true`로 명시해서 생성 diff를 검토한다.
이 기본값 변경으로 기존 시험 로직의 C 소스는 수정하지 않았다.

| 빌드 경로 보완 후 원본과의 차이 | 위 두 vcxproj의 Release include 경로만 변경 |
| 빌드 대상과 의존 프로젝트/소스 참조 | 42개 프로젝트, 1,476개 참조, `FAIL=0` |
| ScenarioEngineTest Debug x64 | 빌드 성공 |
| DSRC / ITSK-00126 v1 / ITSK-00144-2 에뮬레이터 Debug x64 | 모두 빌드 성공 |
| TDC / JSON 코드 생성 도구 Debug x64 | 모두 빌드 성공 |
| 엔진과 세 에뮬레이터 Release x64 | 모두 빌드 성공 |
| MSI 입력 파일 준비 스크립트 | 성공 (MSI 생성/설치 미실행) |
| 별도 경로 새 체크아웃 | 공백 포함 경로에서 엔진·세 에뮬레이터 Debug x64 빌드 성공, `FAIL=0`, 작업 트리 clean |
| GitHub 게시 및 LFS 확인 | `main` 게시 완료, GitHub에서 새로 clone한 4,044개 원본 파일과 SDK SHA-256 일치, `git lfs fsck` 성공 |

검증은 현재 Windows PC의 별도 체크아웃에서 수행했다. 별도 물리 PC에서 직접 실행한
결과는 아니다. 새 체크아웃 빌드 시 `OPEN_SSL_SDK_ROOT` 환경 변수를 존재하지 않는
경로로 설정했으며, MSBuild가 새 체크아웃의 `.deps/sdk/OpenSSL-Win64`를 사용하는
것을 확인했다. 빌드 후 Git 작업 트리에 변경이 없었다.

GitHub 재다운로드 검증의 소스 커밋은 `6e69c3ad243ecfd3e3945b895eaf7ef66ad2d0e8`이다.
이 검증 기록을 추가하는 후속 커밋은 문서만 변경한다.
SDK 아카이브는 69,452,911바이트이며 SHA-256은
`c49a37db4cfcf536de4792a3b01cf8d253a61f55d053a0eeb6aacee2389272f2`이다.

빌드에서 기존 코드의 컴파일러 경고가 발생한다. 경고 수정과 이전 검토에서 발견한
엔진 초기화·비동기 설정 문자열·오류 전파 문제는 이번 소스 통합과 분리한 후속 작업이다.
실장비 표준적합성시험, 서버 연동, MSI 설치 시험은 이번 빌드 검증에 포함되지 않는다.

## 포함되어 있지만 기본 검증 대상이 아닌 항목

- Win32, 구형 Visual Studio 및 Borland 프로젝트.
- 공통 SDK의 개별 데모/테스트 프로젝트. 원본 SDK에는 일부 오래된 데모의
  파일 참조가 이미 누락되어 있다. 주 엔진, 세 에뮬레이터와 생성 도구의 참조 그래프는
  위 구조 검사 대상으로 별도 확인한다.
- ASN.1 스키마에서 C 코드를 다시 만드는 별도 컴파일러. 현재 생성 C 소스는 포함되어
  있으며 기본 엔진 빌드에 별도 ASN.1 컴파일러 설치는 필요하지 않다.
- Visual Studio Installer Projects 확장을 통한 MSI 빌드/설치.
