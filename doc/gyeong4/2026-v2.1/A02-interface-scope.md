# A02 — 역할·인터페이스·적용 범위

관련 업무: **GM-63 / A02**. 선행: [A01](A01-baseline-and-structure.md). 기준: [분석 묶음](README.md).

## 1. 범위와 역할 해석

- 이번 작업은 아래 모든 연계의 **분석**을 포함한다. 코드 구현·실장비 시험은 이번 범위에서 제외한다.
- 표의 ‘분류’는 **후속 개발/시험 범위 제안**이다. `대상`은 기존 경4 시험 경로를 유지하며 상세설계할 후보, `확인 필요`는 새 연계 또는 계약·시험 책임이 정해지지 않은 항목이다. 이 제안은 발주/채택 범위의 확정이 아니다.
- `센터`는 통합교통관제시스템이다. 화살표는 업무 데이터 방향이다. AP-DATEX 연결을 누가 먼저 여는지, MQTT Client/Broker 역할, 시험 에이전트 역할과 구분한다.
- 모든 `A→B`는 SUT=A일 때 **송신시험**(에이전트는 B), SUT=B일 때 **수신시험**(에이전트는 A) 후보다. 센터가 수신한다고 해서 TCP server라는 뜻은 아니다.
- 기존 시나리오 이름은 **에이전트가 맡는 역할**로 읽는다. 예를 들어 `centerClient2rse`는 에이전트가 센터 client로 접속하여 RSE의 BSM 제공 기능을 시험한다. 반대편 센터 수신 기능은 `rseServer2center`로 시험한다.

## 6. 경로별 시험 관측값과 입력·출력

아래는 후속 시험 설계에 필요한 **INTERPRETATION**이며 새 합격 수치가 아니다.

| 경로 | 에이전트가 제공할 입력 | SUT 결과·기록할 관측값 | 현재 미정인 계약 |
|---|---|---|---|
| MQTT/V2N | 브로커 접속, 위치/격자 이동, BSM 또는 SPaT/RSA/TIM | client ID, Topic, SUBACK, 원시 payload/길이, type/version/fid/psid, MessageFrame ID, 수신시각, LWT·재접속·해지 | REF09, QoS/retain/보안·격자 코드·지연 기준 |
| AP-DATEX | 로그인·구독·재전송/취소·EAM·UPER | 양 도메인, 세션·구독 ID, EAM OID, PSID/확장 type, 원시 BER/UPER, 디코딩값, 응답/취소시각 | REF08 판·규격 OID와 EAM OID 관계, 적용 구간 |
| API JSON/XML | 선택된 서버/클라이언트 역할에 맞는 요청 또는 응답 | 요청 방법/주소/매개변수, 상태코드(HTTP 확정 시), raw body·문자 인코딩, 필드/키·타입·누락, 객체 수, 생성/수신시각 | endpoint·인증·오류 응답·JSON 키·base64 범위 |
| DB UTF-8 | 기준 시각·기준 행을 갖는 조회/변경 데이터셋 | DB 스키마·컬럼·키·NULL, 원시값·문자수/바이트수, 수집시간, 갱신/조회시각·트랜잭션 경계 | DBMS·접속·읽기/쓰기 방식·폴링/스냅샷 |

단방향 수신 로그는 SUT 내부 반영을 입증하지 않는다. 브로커 수락과 수신 애플리케이션 처리도 별도 관측이다. 왕복시험에는 입력 사건과 결과를 연결하는 ID/시간 기준이 필요하다.

## 7. A02 완료 조건 검토

목록 35행, OID/개념상 추가 항목 8개에 고유 ID와 대상/제외/확인 필요 분류를 부여했다. 양방향 SUT 역할 규칙과 기존 에이전트 이름의 의미를 명시했다. 실장비·발주 범위 확정은 남아 있으며 불명확한 연결을 구현 업무로 확대하지 않았다.
