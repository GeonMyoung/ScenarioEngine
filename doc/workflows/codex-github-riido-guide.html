PR을 유지하면 얻는 것

열린 Codex 대화에 어떻게 돌아오나요

반자동 운영에서는 중앙 대화의 검토 결과를 읽고 같은 작업을 이어갑니다. 프로그램에서 재개하려면 App Server의 세션·실행 인터페이스를 사용하는 클라이언트를 구성할 수 있습니다. 기존 데스크톱 대화와 연결할 수 있는 범위는 실제 실행 환경에서 검증해야 합니다.

CLI 실행으로 시작하는 방법

codex exec는 스크립트에서 작업을 수행하고 JSON 형태의 진행·결과를 내보낼 수 있습니다. 중계 실행기는 이 결과를 저장할 수 있습니다. CLI 실행의 결과가 앱 대화에 자동으로 표시되는 연결도 별도로 정해야 합니다.[5]

상태는 한 담당이 최종 판단합니다

GitHub 이벤트는 개발 진행을 알려 줍니다. 업무 완료는 Riido에 적힌 조건으로 판단합니다. 자동 상태 전환과 중앙의 기록이 서로 덮어쓰지 않도록 상태별 담당을 지정합니다.

PR 검사 실패보완 필요와 실패 근거 기록중앙 검토 또는 승인된 중계 규칙. 한 검사 실패를 전체 작업 취소로 처리하지 않음
PR 병합병합된 버전 기록중앙이 작업별 완료 조건을 판단. Riido 기본 “병합 → 완료”는 이 정책과 맞도록 조정
Riido 요구사항 변경기준 버전 갱신·영향 검토작업 시작/재개와 제출 직전 재조회. 실행 중이면 현재 변경을 보존하고 영향부터 확인
완료 반영완료 조건·커밋·검증 결과 저장중앙 담당. 기록 후 상태 분류와 실제 저장 내용을 다시 조회

같은 이벤트는 한 번만 처리

GitHub delivery ID와 저장소·PR·head SHA를 처리 기록에 남깁니다. 다시 도착한 이벤트는 기존 결과를 확인합니다. 재전송과 실패 재처리 방법도 마련합니다.[7]

오래된 결과가 새 상태를 덮지 않게

반영 직전에 PR head와 Riido 수정 시각을 재확인합니다. 요구사항이나 커밋이 바뀌었으면 이전 검토 결과의 적용을 보류합니다.

알림이 알림을 만드는 순환 방지

중앙이 작성한 동기화 기록에는 출처와 처리 ID를 표시합니다. 같은 기록의 되돌아온 알림은 새 개발 지시로 사용하지 않습니다. 의미 있는 변경만 다음 실행으로 연결합니다.

작업별로 결과를 나눠 기록

하나의 PR에 여러 업무가 있으면 각 Riido 작업의 산출물·완료 조건을 대조합니다. 여러 작업 키가 native 연동에서 어떻게 연결되는지도 도입 시험으로 확인합니다.

현재 사용할 작업 상태

2026-09-15 운영 구성에서 검토 대기와 검토 완료를 추가하고 API 분류를 확인했습니다. 중앙은 기록할 때마다 최신 상태 목록과 실제 완료 표시를 다시 확인합니다.

표시 이름조회된 분류사용 시점
진행 중inProgress실제 착수·연결 브랜치 생성

기존 ‘완료’와 ‘완료 (1)’은 분류가 맞지 않아 새 완료 반영에 사용하지 않습니다. 기존 작업의 과거 상태와 판단은 보존했습니다.

우리 환경에 적용하는 순서

먼저 작은 작업 하나로 연결을 확인합니다. 예를 들어 문서 한 곳을 수정하는 업무로 시작하면, 개발 환경과 실장비 조건의 영향을 줄이면서 흐름을 확인할 수 있습니다.

  1. Riido 작업과 저장소를 매핑

    ScenarioEngine은 GM-60과 연결합니다. prj22는 Agent와 Web 저장소를 구분해 각각의 Riido 프로젝트·팀·작업 키를 확인합니다. 이름이 비슷해도 같은 대상으로 추정하지 않습니다.

    남길 결과프로젝트 ID, 저장소, 로컬 경로, 중앙 검토 대상의 대응표

  2. GitHub 연동의 실제 권한 확인

    Riido의 설정 → 워크스페이스 → 외부 연동 → GitHub에서 대상 저장소를 연결합니다. 공식 안내는 Organization 선택을 설명하므로, 현재 GeonMyoung 계정의 저장소 설치·접근 가능 범위를 함께 확인합니다.[1]

    남길 결과작업 키가 포함된 브랜치와 시험용 PR이 해당 Riido 작업에 나타나는지 확인

  3. 상태 전환과 쓰기 담당 결정

    진행 상태의 자동 전환과 중앙의 최종 완료 판단을 구분합니다. 현재 완료 분류를 정비하고, 기본 ‘Merge → 완료’ 규칙이 중앙 검토를 앞서지 않도록 매핑을 조정합니다.

    남길 결과이벤트별 상태표, 완료 처리 담당, 자료 대기 처리 방법

  4. Codex의 시작·제출 절차 고정

    시작 시 Riido 최신 본문·댓글을 읽고, 제출 시 원격 커밋·검증·미결정을 남깁니다. 기존 작업 폴더를 먼저 확인합니다. 같은 폴더를 동시에 수정하는 작업은 순서를 정합니다.

    남길 결과공통 지침과 제출 보고 형식. 새 요청마다 환경을 복제하지 않는 정책

  5. 반자동 흐름을 한 작업으로 검증

    지시 → 조회 → 커밋·PR → 중앙 검토 → Riido 반영 → 재조회까지 한 번 진행합니다. 작업 창의 제출 시 중앙 검토에 작업 키와 SHA가 전달되는지도 확인합니다.

    남길 결과실제 Riido 작업·PR·커밋·최종 조회 결과를 연결한 운영 증거

  6. 필요한 GitHub 이벤트만 중계

    PR 업데이트, 검사 완료 등 검토를 시작할 사건을 선정합니다. Actions 또는 webhook, HTTPS 수신점, 대기열과 Codex 실행기를 구성합니다. 웹훅 서명과 허용 저장소를 확인하고 외부 입력을 명령 문자열로 바로 실행하지 않습니다.[3][7][8]

    남길 결과중복 이벤트·실패 재시도·PC 오프라인 복구 기록

  7. Riido 변경의 재개 방식 선택

    외부 변경 알림이 지원되면 중계에 연결합니다. 지원이 확인되지 않으면 다음 지시·검토 때 재조회합니다. 자동 주기 조회가 필요해질 때는 대상·주기·중단 조건을 정해 별도로 활성화합니다.

    남길 결과최신 요구사항이 Codex 입력에 포함되는 시점과 방법

작업 폴더는 적게, 이력은 오래

ScenarioEngine 기본 작업 폴더 + 필요 시 1개 prj22 Agent 기본 작업 폴더 + 필요 시 1개 prj22 Web 기본 작업 폴더 + 필요 시 1개

브랜치·커밋·PR은 GitHub에서 추적합니다. 작업 파일은 기존 환경을 재사용합니다. 읽기 전용 검토는 특정 커밋을 읽고, 추가 폴더가 필요한 실제 동시 수정만 분리합니다.

기존 폴더 수가 정책보다 많으면 미커밋 변경·활성 작업·보관 자료를 확인해 정리합니다. 수량을 맞추기 위한 일괄 삭제는 운영 절차에 넣지 않습니다.

현재 ScenarioEngine에는 .local/coordination/workers.json과 review-state.json이 있습니다. 이 구조를 확장해 작업·저장소·검토 버전을 연결할 수 있습니다. 인증 정보는 저장하지 않습니다.

평소 사용할 작업 지시 예시

Riido의 GM-74를 진행해줘. 최신 요구사항과 선행 조건을 확인하고, 기존 작업 환경에서 구현·검증한 뒤 GitHub에 제출해줘. 중앙 검토에 작업 키와 정확한 커밋, 검증 결과, 미결정 사항을 전달하고, 검토가 끝나면 Riido에 반영된 결과를 다시 읽어 다음 작업을 정리해줘.

요구사항이 바뀌었을 때

“GM-74에 새 댓글을 남겼어. 변경 내용을 확인하고 이어가줘.”

즉시 재개 연결을 구성했다면 알림으로 처리할 수 있습니다. 반자동 운영에서는 이 지시가 최신 내용 조회의 계기가 됩니다.

진행 상황이 궁금할 때

“ScenarioEngine 작업별 최신 커밋과 검토 결과, Riido의 남은 조건을 보여줘.”

진행률은 Riido의 완료 조건과 실제 상태를 기준으로 요약하고, 코드 버전과 검사 결과를 함께 연결합니다.

연동이 준비됐다고 볼 수 있는 확인 항목

작업 키로 시작하면 맞는 Riido 작업과 저장소를 조회한다.

브랜치·PR이 해당 작업에 연결되고 실제 상태를 확인할 수 있다.

자료 대기 작업은 문서 제출이나 병합 후에도 남은 조건이 보존된다.

새 커밋·요구사항 변경이 있으면 오래된 완료 판단을 적용하지 않는다.

중복 알림·재시도·네트워크 오류가 중복 댓글이나 잘못된 완료를 만들지 않는다.

다음 Codex 실행이 갱신된 Riido 상태를 읽고 기존 작업 폴더를 재사용한다.

권장 도입안

반자동 운영을 먼저 정착시키고, GitHub 이벤트 전달을 다음 단계로 추가합니다. 이 순서라면 기존 Codex 작업 창·GitHub 저장소·Riido 목록을 활용할 수 있습니다. 요구사항 변경의 실시간 재개는 Riido 알림 지원과 Codex 실행 환경을 확인한 뒤 연결합니다.

인쇄본에는 자동화 방식 세 가지가 모두 표시됩니다. 단계별 시뮬레이션은 HTML에서 조작할 수 있습니다.
