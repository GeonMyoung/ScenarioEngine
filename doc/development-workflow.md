# 개발 작업 방식

사용자 요청을 기준으로 분석·구현하고 필요한 검증을 수행한 뒤 결과를 보고한다.

합의한 설계·구현 원칙은 [개발 정책](development-policy.md)에서 관리한다. 경4의 상세 범위와 진행 상태는 해당 정책 문서의 연결 문서를 따른다.

- 기존 작업 폴더와 변경을 보존한다. 새 요청마다 별도 환경을 만들지 않는다.
- 검증은 변경 영향에 맞추며, 작은 문서 변경에 전체 빌드나 테스트를 추가하지 않는다.
- GitHub 커밋·push·PR은 사용자가 요청한 범위에서 수행한다.
- Riido 기반 업무 진행 정책은 사용자 요청으로 폐기했다. 업무 번호나 과거 연결 여부와 관계없이 Riido 조회·등록·상태/댓글 갱신, 실행 등록, 중앙 인계·검토 대기·receipt를 개발 절차로 수행하지 않는다.
- 기존 업무 내용과 표준 근거는 저장소 자료와 사용자 지시를 사용한다. 과거 연동 문서·실행 기록은 참고 이력이며 현재 운영 지침이 아니다.
- 별도의 재도입 요청 전에는 연동 정책·스킬·자동 조회를 복구하지 않는다. 이전 대화의 자동 인계 약속보다 이번 폐기 지시를 우선한다.
