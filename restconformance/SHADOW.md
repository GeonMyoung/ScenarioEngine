# 음영구간 미시교통정보 요청·제공 시험

제3부 제4장 2.3 표 4-21 `SHAD_TRAF_INFO`와 제4부 제4장 1.1.1·1.2.1의 Open API 시험방법을 적용한다. 정상 데이터는 표준 정의표를 우선하고 호출 및 명확한 오류응답은 회신 자료의 OpenAPI 1.3을 따른다.

| 설계 ID / 등록 ID | 시험 대상 | 시험 시스템 | 엔진 case |
|---|---|---|---|
| SC10 / 64 | 통합교통관제시스템, HTTP Client | 음영구간 미시교통정보 플랫폼, HTTP Server | `microServer2center_shadow_v1` |
| SC31 / 65 | 음영구간 미시교통정보 플랫폼, HTTP Server | 통합교통관제시스템, HTTP Client | `centerClient2micro_shadow_v1` |

구분 C2C. 업무 정보는 플랫폼 → 통합교통관제시스템으로 전달된다. 요청·제공 시험명은 시험 대상의 역할을 가리킨다.

## 계약과 판정

- `GET /data`, JSON. `since`는 선택 정수(기본 0, 명세에 최소값 없음), `node_link`는 선택 문자열, `latest`는 선택 정수 0~500(기본 0)이다. 설정에서 빈 값은 해당 변수를 생략한다. URL 인코딩 후 전송한다.
- 요청시험에서는 준비한 설정과 실제 요청변수의 의미가 일치해야 한다. 순서는 무관하며 since/latest의 생략과 명세 기본값 0은 동일하게 본다. 중복·미정의 변수·GET 본문을 거부하는 것은 현재 시험 조건이다. API의 중복/추가 변수 처리 규범을 확보했다는 뜻은 아니다.
- 인증 정의가 없어 인증변수·헤더·자격정보 오류시험을 만들지 않았다. 운영 서비스에 인증이 필요 없다고 확정한 것은 아니다.
- 정상 200의 OpenAPI schema는 `{}`다. **표준 예시의 루트 JSON 배열을 프로젝트 기준으로 채택**했다. 응답 포장을 운영 API와 대조한 결과로 표현하지 않는다.
- 배열의 각 레코드는 아래 필드를 모두 포함해야 한다. 숫자 문자열·boolean·null은 숫자로 변환하지 않는다. JSON 정수는 수학적 정수값이므로 `18.0`, `42e0` 등도 범위 내이면 허용한다. 작은 소수부를 반올림해 통과시키지 않는다.

| 필드 | 검사 기준 |
|---|---|
| time | 문자열, YYYYMMDDhhmmss, 실제 달력·시분초 범위 |
| node_link | 정수 0~99999 |
| lane_no | 정수 0~350 |
| lane_speed | 정수 0~350 |
| lane_volume | 정수 0~99999 |
| lane_density | 정수 0~350 |

잘못된 요청은 `latest=501`을 보내 명세의 HTTP 422를 검사한다. 본문은 JSON 객체이며 `detail`은 선택이다. 제공되면 배열이어야 하고 각 항목의 `loc`(문자열/정수 배열), `msg`(문자열), `type`(문자열)이 필수다. 명세에 없는 비어 있지 않음 조건을 추가하지 않는다.

자료 부재는 같은 유효 경로·조회조건에 자료가 없는 상태를 준비한다. 기본 오류 HTTP 404, 미존재 경로 404, 서버 오류 500, 추가 빈 정상응답 200/204는 프로젝트의 설정 가능한 기준이며 모두 공식 고정 코드라고 설명하지 않는다. 자료 부재용 422는 문서상 조회변수 오류와 구분되는 임시 상태코드 기준으로만 사용한다.

## 선택 항목

| 대상 | 시험방법 요구 확인 | 추가 검증 | 합계 |
|---|---|---|---|
| 통합교통관제시스템 | 정상 요청, 자료 부재 오류응답 조건의 요청 | 422·404·500·빈 정상·손상 응답 조건의 요청 | 7 |
| 음영구간 플랫폼 | 정상 제공, 잘못된 조회변수 오류응답, 자료 부재 오류응답 | 미존재 경로 오류응답, 빈 정상응답 | 5 |

각 항목 최소 10회 반복. 제공시험의 정상 자료·자료 부재 오류·빈 정상응답은 서로 다른 준비 조건이므로 별도 실행한다. 자료 부재 조건 확인란은 준비 확인이며 대상 내부 조회 결과를 직접 관측했다는 뜻이 아니다.

## 실행

등록 파일과 예시 설정은 [registration](registration/)에 있다. 별도 설치·배포 없이 현재 개발 엔진으로 검증했으며 에뮬레이터를 시험 대상으로 사용했다.

1. SC10은 엔진을 HTTP Server로 대기시키고, SC31은 상대 제공 서버를 먼저 준비한다. 플랫폼의 실행 채널에 해당 엔진을 연결하고 예시 설정을 입력한다.
2. `emulator/shadow_sut.py --role requester`는 통합교통관제시스템 역할, `--role provider`는 음영구간 플랫폼 역할이다. `--port`, `--output`은 필수다. `--params`는 조회변수 JSON이며 requester의 값은 엔진 설정과 맞춘다. `--requests`는 선택 항목 수×반복수다.
3. 제공측 자료 조건은 `--data normal`, `absent`, `empty`로 구분한다. 자료 부재 시험은 엔진의 `confirm_data_absent`도 선택한다.
4. 각 요청·응답을 회차별로 전부 표시·저장한다. 긴 자료는 분할하고 자격정보가 있으면 가린다. 정상·오류·손상 자료 원문을 함께 보관한다.
5. 엔진은 REST-AUTO-001의 자동 관측 범위로 종료한다. 상세시험 START→SUCCESS/FAIL/STOPPED, 전체 FINISH 1회이며 COMPLETE는 사용하지 않는다. 대상 기록 자동 대조는 선택 기능이다.

에뮬레이터는 고정 시험자료의 송수신·형식·오류처리를 구현한다. 실제 since 커서의 누적 데이터 처리, node_link 필터 결과, latest 결과 정렬/선택의 업무 로직은 모의 구현·판정 범위가 아니다. 설정값의 실제 전달과 JSON 구조 검사는 수행한다. 운영 필터·커서 검증에는 준비 데이터셋과 응답 포장·총 데이터 값의 확정이 필요하다. `/data/total_count`, `/status`는 이번 정보교환 시험에 불필요하며 200 응답 구조도 미정이므로 별도 시험으로 추가하지 않았다.

## 차이와 범위

- 표준 예시 `time:"2026-07-24 13:20"`, `node_link:"3020023700"`, 속도·밀도의 소수값은 정의표와 충돌한다. 정의표를 적용하고 자동 보정하지 않는다. `18.0`처럼 정수값인 숫자는 충돌로 취급하지 않는다.
- 정상 응답 배열 채택, 인증, 자료 부재 오류 코드, 커서·필터 결과의 운영 계약은 후속 확인 대상이다.
- 1분 연계주기와 실제 시스템의 내부 처리·상호운용은 이번 최소 10회 단일 요청 교환의 검증 결과로 주장하지 않는다.
- 응답 크기는 기존 어댑터의 1 MiB 한도다.
