차량–센터 MQTT/V2N 간편시험

설치된 ScenarioEngine과 같은 PC의 Broker·상대 에뮬레이터를 연결합니다. 웹에서 실행하고, 실행기와 웹 보고서에서 결과를 확인합니다.

시험 선택 → 토픽 입력 → 웹 환경설정 적용 → 시험 시작 → 결과 확인

준비

ScenarioEngine MSI {{MSI_VERSION}}과 기존 표준적합성시험 웹 연결 Chrome 확장이 필요합니다. 엔진과 Python은 설치 폴더의 실행본을 사용합니다. 이 묶음에는 시험용 Broker와 상대 실행 도구가 들어 있습니다.

MQTT 인증 입력

인증을 사용하는 Broker의 Username·Password를 시험환경설정에 직접 입력합니다. 별도 인증 파일은 준비하지 않습니다. 사용자 선택에 따라 화면에는 입력한 값이 그대로 표시됩니다. 인증 없는 Broker는 두 값을 비워 둡니다.

실행 순서

  1. 시작하기.exe를 열고 시험 대상과 시나리오를 선택합니다.
  2. 메시지별 실제 사용할 토픽을 입력합니다. 대소문자와 슬래시를 그대로 사용합니다. SPaT·TLSM 토픽을 같게 입력해 공유할 수 있습니다. 확인 건수를 입력하고 상세시험을 선택합니다.
  3. Chrome에서 웹 시험 열기를 눌러 자체 시험 수행으로 새 회차를 만듭니다. Agent 접속 URL을 복사해 실행기에 붙여넣습니다.
  4. 웹 환경설정 적용을 누릅니다. 실제 웹 입력칸과 설정 버튼을 통해 엔진에 반영합니다. 값이나 선택 항목을 바꾸면 다시 적용합니다.
  5. 웹에서 시험 시작을 누릅니다. Broker와 상대가 준비된 뒤 웹 시험을 시작합니다. 웹의 시작 버튼을 직접 눌러도 같은 준비 절차를 거칩니다.
  6. 진행 중에는 송수신 자료에서 메시지 순번별 원문과 판정 근거를 확인합니다. 웹 결과 보기는 저장 보고서, 시험 기록 보기는 이번 실행의 전체 메시지와 판정 자료를 엽니다. 직접 확인 표시는 사용자가 확인한 뒤 남깁니다.

BSM 발행시험의 성공 표시

최신 개발본은 V2N version 0과 회차별 다른 BSM 시험값을 사용합니다. 송신 CSV의 msgCnt·secMark·위치·속도·방향 값으로 수신 로그를 대조할 수 있습니다. 전달받은 J2735_20240923_KSR1600 스키마의 필수 vert를 적용합니다.

센터가 시험대상인 BSM 시험(#81)은 토픽·발행 횟수를 입력하면 1초 주기·QoS 0으로 발행 후 종료합니다. 공통 Broker 접속 설정은 유지합니다. 시험 중 수신 로그를 기다리지 않습니다.

자동 성공은 발행 절차 완료입니다. 최종 합격은 센터의 수신 로그를 사후 대조하여 결정합니다. 송신 원문·시각·순번·해시가 담긴 bsm-transmit.jsonl 및 CSV를 시험 기록 폴더에 저장합니다.

간편실행기는 #81에서 Broker만 준비하며 상대 에뮬레이터는 실행하지 않습니다. 실제 센터 시험에서는 대상의 구독 준비를 먼저 확인하세요.

센터 정보제공시험의 처리 순서

#84·#85·#86은 각각 해당 메시지의 토픽과 상세시험에 필요한 설정을 표시하고 회차별로 결과를 저장합니다. 아래 순서는 종합점검 #82에 적용됩니다.

SPaT 수집·검증 완료 → TLSM 수집·검증 완료 → TIM 수신·검증 완료 → 전체 종료

선택한 메시지를 순서대로 처리합니다. QoS는 0입니다. 구독 완료 후 SPaT·TLSM은 각각 입력한 수신 건수(기본 10건)의 데이터 정합성을 확인합니다. TIM은 제한속도 변경·속도 유지·좌측 차로 변경·우측 차로 변경·갓길 주행을 furtherInfoID와 ITIS 조합으로 식별합니다. 선택한 종류별 확인 건수(기본 1건)를 적용합니다. content 형식은 수신 기록에 표시하며 합불 기준에서 제외합니다. 중복은 종류별 확인 건수에 합산하지 않습니다.

수신 총 제한시간 없이 목표 건수를 기다립니다. 중지를 누르면 확보한 원문과 아직 확인하지 못한 항목을 기록합니다. 브로커 접속·구독 응답과 데이터 규격 오류는 각 실패 사유를 표시합니다.

자동으로 준비하는 항목

같은 PC의 MQTT Broker, 선택 메시지의 상대 Publisher/Subscriber, 수신 관측 파일을 회차별로 준비합니다. 제공 상대는 시험기의 구독 준비가 끝난 뒤 발행합니다. 수신 상대는 구독을 마친 뒤 시험 자료를 받습니다. 설정 적용만으로 정보교환을 시작하지 않습니다.

자동 결과는 에뮬레이터 환경의 개발 검증입니다. 실제 차량·센터의 적합 판정과 구분합니다. 수신시험은 Broker ACK와 상대가 실제 받은 자료를 별도로 확인합니다.

시험이 실패했을 때

실패한 행을 선택하면 아래 설명에 확인된 사실, 검사 위치·실제값·범위와 추가 점검 사항이 나타납니다. 읽지 못한 값은 추정하지 않습니다.

미수신은 대상 미발행·토픽 오류·망 유실 중 원인이 아직 확정되지 않은 상태입니다. 실제 토픽, 대상의 발행 및 Broker 로그를 함께 확인하세요. 앞선 실패로 실행하지 않은 항목은 실행기에서 미실행으로 표시합니다.

현재 웹 보고서 요약표는 미실행 항목도 실패로 표시하고 실패 종료 시각을 비워 두는 제약이 있습니다. 실제 수행 여부와 실패 사유는 상세 로그와 간편실행기 기록을 함께 확인하세요.

연결이 되지 않을 때

  • 같은 시험의 새 회차 Agent URL인지 확인합니다.
  • Chrome의 공통 웹 연결 확장이 활성화되어 있는지 확인합니다. 새 권한 추가는 필요하지 않습니다.
  • 토픽이 비어 있거나 설정을 바꿨다면 다시 입력·적용합니다.
  • 시험 중 중지를 누르면 이번 실행에서 시작한 프로세스를 정리하고 수집 기록을 남깁니다.
