Kafka 시험을 하나씩
설정하고 확인하세요

공통 확장과 동시 실행

DATEX·REST API·TCP/Binary·Kafka는 표준적합성시험 웹 연결 확장 하나를 사용합니다. 진행 중인 시험을 마친 뒤 기존 REST 확장을 새로고침하고, 이전 DATEX 전용 확장은 꺼 주세요. 새 시험 탭에서 사용합니다.

동시 시험마다 실행기 창과 별도의 시험 회차를 엽니다. 최대 16개 회차를 구분하고 같은 회차의 중복 제어를 막습니다. 충돌하는 로컬 포트는 설정 적용 시 변경값을 웹에 표시해 조정합니다.

공통 확장 사용 안내에서 갱신 및 새 PC 설치 순서를 확인하세요.

시작하기.exe를 실행하면 브로커와 상대 프로그램을 함께 준비할 수 있습니다. 웹에서 실제 설정을 적용하고, 원하는 항목만 선택해 시험합니다.

ZIP 전체를 새 폴더에 풀어 사용하세요. Python·Java·Kafka가 포함되어 있으므로 Docker·WSL·별도 런타임 설치가 필요하지 않습니다. 같은 PC의 독립 상대를 이용하는 개발 검증용 묶음입니다.

시험 순서

1. 대상과 상세시험 선택

상단에서 시험 대상을 고릅니다. 처음에는 한 항목만 선택되어 있습니다. 상세시험 선택 탭에서 절차와 기대 결과를 읽고, 선택 행만·복수·전체 선택을 사용하세요.

2. 새 웹 시험 열기

Chrome에서 웹 시험 열기 → 웹의 자체 시험 수행 → Agent 접속 URL 복사 순서로 진행합니다. 실행기의 주소란에 붙여 넣으세요. 이전에 사용한 주소 대신 매번 새 시험 회차를 만듭니다.

3. 합의한 환경설정 적용

토픽·Group ID·포장·반복수·주기를 확인합니다. 토픽은 시험 전에 합의한 값을 직접 입력합니다. 기본으로 보이는 토픽은 자료의 예시이며 빈 값은 실행할 수 없습니다. 사용 중인 포트라면 빈 포트 찾기를 사용하세요.

웹 환경설정 적용을 누르면 실제 Chrome 입력칸과 체크박스에 반영되고, 웹의 설정 버튼으로 엔진에 전달됩니다. 설정만 적용한 동안 브로커·상대·시험은 시작하지 않습니다.

4. 시험 시작

실행기의 웹에서 시험 시작 또는 웹의 시험 시작을 누릅니다. 실행기는 이 회차의 전용 브로커와 합의 토픽·상대를 준비합니다. 웹에서 직접 설정을 바꾸어도 실제 수락값이 상대에 반영됩니다. 입력을 수정했다면 반드시 다시 설정을 적용하세요.

5. 결과를 직접 확인

웹의 시험 제어 화면에서 각 회차의 내용·발송 주체·토픽·offset·판정 근거를 확인합니다. 웹 결과 보기는 저장 보고서, 시험 기록 보기는 읽기 쉬운 시험 결과를 엽니다. 원문과 독립 상대 기록은 상세 진단(고급)에서 확인합니다. 자동 성공과 사용자의 확인은 별도입니다. 확인을 마쳤을 때 결과 확인 완료 표시 → 다음 항목을 사용하세요.

시간과 데이터 설정

  • 정상 정보교환은 기본 10회입니다. 주기 항목은 별도 표본 2개 이상을 사용합니다.
  • 기본 주기: 오픈데이터 60초, 플랫폼 상태 600초, 시설/MAP 60초, I2X 상태 10초. 플랫폼 상태 주기 항목은 약 10분 이상 걸립니다.
  • 주기를 줄이면 변경된 개발 시간 조건으로 기록됩니다. 기본 시간의 검증으로 간주하지 않습니다.
  • 오픈데이터 포장은 json 또는 base64-json을 상대와 같게 설정합니다. 자동 추정하지 않습니다.
  • 시설정보 준비자료는 포함한 MAP JSON 예시를 개발 자료로 선택해 둡니다. 실제 합의 자료로 파일 경로를 바꿀 수 있습니다. 시설 전용 토픽의 업무 의미 전체를 검증하는 항목은 아닙니다.
  • 포함한 브로커는 127.0.0.1 전용 PLAINTEXT입니다. 외부 브로커·인증·실장비 시험은 일반 Kafka 시험 엔진으로 별도 구성합니다.

중지하거나 문제가 생기면

중지 또는 웹의 시험 종료를 누르면 수집한 자료를 보존합니다. 실행기가 만든 프로세스만 정리하며, 다른 프로그램과 기존 브로커를 종료하지 않습니다.

현재 플랫폼은 STOPPED를 받더라도 상세 상태가 ‘시작’으로 남거나 중지 보고서를 생성하지 않을 수 있습니다. 실행기는 중지를 별도로 표시합니다. 중지 결과는 상세 진단(고급)의 easy-outcome.json과 kafka-results에서 확인하세요.
  • 확장 연결 실패: 기존 REST/TCP 실행기의 연결을 해제하고, Chrome 확장이 켜진 상태에서 새 자체 시험 탭을 엽니다.
  • 다른 시험/이미 사용한 주소: 같은 시험의 새 회차 주소를 복사합니다.
  • 포트 충돌: 빈 포트를 선택한 뒤 웹 설정을 다시 적용합니다. 기존 점유 프로그램을 자동으로 중지하지 않습니다.
  • 경로가 너무 길다는 안내: 묶음을 C:\Kafka-Test처럼 짧은 경로로 옮깁니다.

완료 범위와 검증 결과는 검증결과.json을 확인하세요. 대상 내부 업무 처리, 전체 MAP/시설 의미, 실장비 상호운용 및 Broker 제품 전체 적합성은 이 묶음의 자동 판정 범위에 포함하지 않습니다.

포함 실행환경: Apache Kafka 3.9.1 · Eclipse Temurin JRE 17 · Python 3.12 · confluent-kafka 2.8.0. 각 실행환경의 라이선스와 NOTICE는 runtime 내부에 보존합니다.

공통 시험 기록 보기

시험 안내 → 준비 → 진행 → 송신·수신 → 판정 근거 → 결과의 순서로 기록합니다. 목적·기준·실제 자료·확인 범위를 함께 확인하세요. 시험 기록 보기는 사용자용 결과를 열며, 내부 실행 정보와 파일은 상세 진단(고급)에서 확인합니다. 자동 판정과 직접 확인 완료 표시는 별개입니다.
