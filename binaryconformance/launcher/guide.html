공통 확장과 동시 실행

DATEX·REST API·TCP/Binary·Kafka는 표준적합성시험 웹 연결 확장 하나를 사용합니다. 진행 중인 시험을 마친 뒤 기존 REST 확장을 새로고침하고, 이전 DATEX 전용 확장은 꺼 주세요. 새 시험 탭에서 사용합니다.

동시 시험마다 실행기 창과 별도의 시험 회차를 엽니다. 최대 16개 회차를 구분하고 같은 회차의 중복 제어를 막습니다. 충돌하는 로컬 포트는 설정 적용 시 변경값을 웹에 표시해 조정합니다.

공통 확장 사용 안내에서 갱신 및 새 PC 설치 순서를 확인하세요.

8개 시험 구성의 52개 상세항목을 하나씩 실행하고 확인합니다. 같은 PC의 상대 프로그램을 시험 대상으로 사용하며 엔진·Python은 묶음에 포함되어 있습니다.

한 항목씩 실행하기

  1. 시작하기.exe를 열고 시험 대상과 정보를 선택합니다.
  2. 환경설정의 주소·포트·반복수·운용 기준을 확인합니다. 기본값 채우기와 빈 포트 찾기는 입력값만 바꿉니다.
  3. ‘상세시험 선택’에서 한 항목을 고릅니다. 필요한 경우 여러 항목이나 전체를 선택할 수 있습니다.
  4. ‘Chrome에서 웹 시험 열기’ → 웹의 ‘자체 시험 수행’으로 새 회차를 만듭니다. ‘Agent 접속 URL 복사’를 누르고 실행기에 붙여 넣습니다.
  5. ‘웹 환경설정 적용’을 누릅니다. 웹 입력값·체크박스·설정 요약에 반영된 것을 확인합니다. 설정만 적용하면 시험은 시작되지 않습니다.
  6. 웹의 ‘시험 시작’ 또는 실행기의 ‘웹에서 시험 시작’을 누릅니다. 접속 역할에 맞춰 상대 프로그램이 자동으로 준비됩니다.
  7. 진행 중에도 ‘송수신 상세’를 열어 매회 메시지를 확인할 수 있습니다. 행을 선택하면 원문 HEX·해석 데이터·수집 원본이 표시됩니다. 완료 후에는 ‘웹 결과 보기’에서 저장된 결과도 확인합니다.
  8. 확인했으면 ‘결과 확인 완료 표시’를 누르고 ‘다음 항목’으로 이동합니다. 다음 실행에는 웹에서 새 회차를 만듭니다.

송수신 상세 보기

‘발송 → 수신’은 실제 시스템명입니다. 송신·수신 방향은 시험 시스템 기준이며 ACK/NACK도 실제 송신 주체를 표시합니다. 반복 메시지는 매회 별도 행으로 남습니다.

송신·수신·조립 및 판정 자료를 골라 볼 수 있습니다. 행을 선택하면 새 메시지 자동 따라가기가 꺼져 읽던 자료를 유지합니다. 다시 따라가려면 체크하세요. 긴 표시 자료는 조각이 모두 도착하면 합쳐 보여주고, 아직 덜 도착했으면 수집한 조각과 개수를 표시합니다.

메인 창의 진행 안내는 최근 요약입니다. 송수신 상세는 이전 행을 삭제하지 않으며 원문을 기록 파일에서 읽습니다. 이 변경은 v2로 새로 실행한 시험부터 적용됩니다. 과거 웹 보고서는 수정하지 않습니다.

한 번 접속하고 설정한 횟수만큼 교환합니다

선택한 시험 항목마다 TCP에 한 번 접속하고, 같은 세션에서 환경설정의 횟수만큼 정보를 교환한 뒤 연결을 정리합니다. 별도 정보조회 요청이 없는 현재 연계는 데이터 제공 측이 전송을 시작하고, 명세의 ACK/NACK로 수신 결과를 회신합니다.

회차가 바뀌어도 순서번호는 이어집니다. 변경정보의 최초 준비 자료와 분할 순서번호 오류 뒤의 정상 끝 프레임 복구는 반복 완료 횟수와 구분합니다. 연결이 중간에 끊기면 재접속으로 숨기지 않고 실제 완료 횟수와 중단 원인을 기록합니다.

주기와 오류시험을 확인하세요

TOD Heartbeat의 기본 주기는 60초, 관측 횟수는 2회입니다. 해당 항목은 약 2분 이상 기다려야 합니다. 차량운행정보 주기는 기본 1초이며 10회 교환 시 9개 간격을 검사합니다. 표시된 허용오차는 시험 환경값입니다.

LRC·데이터 길이·순서번호 오류 거부시험은 의도한 오류를 보내고 NACK로 거부되는 것을 성공으로 판정합니다. 오류를 보냈다는 이유만으로 시험 실패가 아닙니다. 최적경로·돌발상황의 ‘자료 없음’은 해당 정보의 접속 조건이며 TOD 주기 시험과 다릅니다.

LRC 계산·ACK 순서번호·문자 인코딩은 현재 채택한 개발 기준입니다. 이 묶음의 성공이 미정 계약의 공식 확정이나 실제 기관 시스템 적합성을 뜻하지 않습니다.

설정 변경과 기록

실행기에서 설정·선택 항목을 바꾸면 다시 적용해야 시작할 수 있습니다. 웹에서 직접 바꿨을 때는 웹의 ‘설정’을 누르세요. 상대 프로그램에도 엔진이 수락한 실제 값이 적용됩니다.

각 회차는 runs의 새 폴더에 저장됩니다. ‘상세 진단(고급)’에서 적용 설정과 엔진·상대의 원문 기록을 볼 수 있습니다. 성공·실패·중지·수행 오류와 사용자의 직접 확인 표시는 구분됩니다. 중지나 창 닫기는 이 실행기가 만든 프로세스만 정리합니다.

확장이 응답하지 않으면 REST 실행기의 연결 상태와 확장 활성 상태를 확인하고 새 자체 시험 탭을 여세요. 사용 중인 TCP 포트는 ‘빈 포트 찾기’ 후 재적용합니다. 중지한 시험의 별도 웹 보고서는 플랫폼 저장 여부를 확인해야 하며 로컬 수집 기록은 보존됩니다.

공통 시험 기록 보기

시험 안내 → 준비 → 진행 → 송신·수신 → 판정 근거 → 결과의 순서로 기록합니다. 목적·기준·실제 자료·확인 범위를 함께 확인하세요. 시험 기록 보기는 사용자용 결과를 열며, 내부 실행 정보와 파일은 상세 진단(고급)에서 확인합니다. 자동 판정과 직접 확인 완료 표시는 별개입니다.
